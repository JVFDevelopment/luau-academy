UI is how players understand your game: health bars, coin counters, shops, menus, notifications. Good UI is clear, responsive on every screen size, and quick to react.

## The UI hierarchy

:::tree
StarterGui
  HUD (ScreenGui) # copied into each PlayerGui
    CoinsLabel (TextLabel)
    ShopButton (TextButton)
    ShopFrame (Frame)
      UICorner (UICorner)
      Title (TextLabel)
      Items (ScrollingFrame)
        UIGridLayout (UIGridLayout)
      CloseButton (TextButton)
    HUDController (LocalScript)
:::

- A **ScreenGui** is a full-screen canvas. Everything in `StarterGui` is copied into each player's `PlayerGui` when they spawn.
- `ResetOnSpawn` (on ScreenGuis) controls whether the UI is recreated on every respawn. Set it to **false** for most HUDs and menus, or their state resets every time the player dies.
- UI is **client-side**. Script it with LocalScripts; the server never sees button clicks — the client sends intents via remotes.

| Object | Purpose |
| --- | --- |
| `Frame` | A container / box |
| `TextLabel` / `ImageLabel` | Display text / an image |
| `TextButton` / `ImageButton` | Clickable; use the `Activated` event |
| `TextBox` | Text input; `FocusLost(enterPressed)` and `.Text` |
| `ScrollingFrame` | Scrollable list; set `AutomaticCanvasSize` |
| `ViewportFrame` | Render 3D models inside UI (item previews) |

## UDim2: scale and offset

Sizes and positions use **UDim2**: `UDim2.new(xScale, xOffset, yScale, yOffset)`.

- **Scale** is a fraction of the parent's size (0 to 1). `0.5` = half.
- **Offset** is in pixels.

```roblox
frame.Size = UDim2.new(0.4, 0, 0.5, 0)       -- 40% wide, 50% tall
frame.Position = UDim2.new(0.5, 0, 0.5, 0)   -- top-left corner at the center
frame.AnchorPoint = Vector2.new(0.5, 0.5)     -- now the CENTER is at the center

button.Size = UDim2.fromOffset(200, 50)        -- exactly 200x50 pixels
bar.Size = UDim2.fromScale(0.75, 1)            -- 75% of parent width, full height
```

`AnchorPoint` sets which point of the element its `Position` refers to: `(0, 0)` top-left, `(0.5, 0.5)` center, `(1, 1)` bottom-right. Centering anything is `Position = UDim2.fromScale(0.5, 0.5)` + `AnchorPoint = Vector2.new(0.5, 0.5)`.

:::tip Scale for layout, offset for details
Pure offset UI looks tiny on a big monitor and overflows on a phone. Pure scale UI stretches into weird shapes. Use **scale** for overall layout and size, and keep shapes correct with a `UIAspectRatioConstraint`. Use small offsets for padding and borders. Always test with Studio's **Device Emulator** (Test tab).
:::

## Layouts, modifiers and constraints

Add these as children of a UI element to change how it or its children behave:

| Object | Effect |
| --- | --- |
| `UIListLayout` | Arranges children in a row or column (`FillDirection`, `Padding`, `SortOrder = LayoutOrder`) |
| `UIGridLayout` | Arranges children in a grid (`CellSize`, `CellPadding`) |
| `UIPadding` | Inner padding |
| `UICorner` | Rounded corners |
| `UIStroke` | Outline (on frames or text) |
| `UIGradient` | Gradient fill — can be animated |
| `UIAspectRatioConstraint` | Keeps width/height ratio fixed |
| `UISizeConstraint` / `UITextSizeConstraint` | Min/max size and text size |
| `UIScale` | Scales an element and its children — great for pop animations |

Set `TextScaled = true` (with a `UITextSizeConstraint` max) so text fits its box on every screen. `AutomaticSize` lets frames grow to fit content.

## Scripting UI

```roblox title="StarterGui › HUD › HUDController (LocalScript)"
local Players = game:GetService("Players")
local player = Players.LocalPlayer
local gui = script.Parent
local coinsLabel = gui:WaitForChild("CoinsLabel") :: TextLabel

local leaderstats = player:WaitForChild("leaderstats")
local coins = leaderstats:WaitForChild("Coins") :: IntValue

local function render()
	coinsLabel.Text = `🪙 {coins.Value}`
end
coins.Changed:Connect(render)
render()
```

This is the core UI pattern: **watch data, re-render text**. The server changes `Coins`; it replicates; the client's UI updates.

### Buttons

Use `Activated` — it works for mouse, touch and gamepad. (`MouseButton1Click` only covers some inputs.)

```roblox
local shopButton = gui:WaitForChild("ShopButton") :: TextButton
local shopFrame = gui:WaitForChild("ShopFrame") :: Frame

shopButton.Activated:Connect(function()
	shopFrame.Visible = not shopFrame.Visible
end)
```

### Animated open/close

```roblox
local TweenService = game:GetService("TweenService")
local scale = Instance.new("UIScale")
scale.Parent = shopFrame

local function open()
	shopFrame.Visible = true
	scale.Scale = 0.85
	TweenService:Create(scale, TweenInfo.new(0.25, Enum.EasingStyle.Back, Enum.EasingDirection.Out), { Scale = 1 }):Play()
end

local function close()
	local t = TweenService:Create(scale, TweenInfo.new(0.15), { Scale = 0.85 })
	t:Play()
	t.Completed:Wait()
	shopFrame.Visible = false
end
```

### Building lists from data

Create one template (kept invisible or in ReplicatedStorage), then clone it per item:

```roblox
local template = script:WaitForChild("ItemTemplate") :: Frame
local list = shopFrame:WaitForChild("Items") :: ScrollingFrame

for i, item in ITEMS do
	local card = template:Clone()
	card.Name = item.id
	card.LayoutOrder = i

	local nameLabel = card:WaitForChild("NameLabel") :: TextLabel
	local priceLabel = card:WaitForChild("PriceLabel") :: TextLabel
	local buyButton = card:WaitForChild("Buy") :: TextButton

	nameLabel.Text = item.name
	priceLabel.Text = `{item.price} coins`
	buyButton.Activated:Connect(function()
		buyRemote:FireServer(item.id)
	end)
	card.Parent = list
end
```

## UI in the world

- **BillboardGui** — always faces the camera, attached to a part (`Adornee`). Use it for name tags, health bars above enemies, and quest markers. `AlwaysOnTop`, `MaxDistance` and `StudsOffset` are key properties.
- **SurfaceGui** — UI on the face of a part: signs, screens, interactive panels.
- **Highlight** — an outline/fill effect on any model or part, great for showing what's interactable.

## Safe areas and the top bar

Phones have notches and Roblox draws its own top bar. `ScreenGui.ScreenInsets` (e.g. `DeviceSafeInsets`) keeps your UI out of unsafe areas; `IgnoreGuiInset` controls whether the ScreenGui starts under the top bar. Keep critical buttons away from screen edges and make touch targets at least ~44 pixels.

:::quiz UI
? What does `UDim2.new(0.5, 0, 0.5, 0)` with `AnchorPoint = Vector2.new(0.5, 0.5)` do?
+ Centers the element in its parent
- Puts its top-left corner at the center
- Makes it half the parent's size
- Nothing — scale and anchor cancel out
> Position is the parent's center, and the anchor is the element's center.

? Which event should a TextButton use to work with mouse, touch and gamepad?
+ `Activated`
- `MouseButton1Click`
- `Touched`
- `InputBegan` on the button
> `Activated` covers all input types.

? Why set `ResetOnSpawn = false` on a HUD?
+ So it isn't destroyed and recreated (losing state) every time the player respawns
- So it loads faster
- So the server can see it
- So it stays on top
> ResetOnSpawn recreates the ScreenGui on each spawn.

? A shop button is clicked. Who should decide whether the purchase succeeds?
- The LocalScript that owns the button
+ The server, after a RemoteEvent/RemoteFunction request
- The ScreenGui
- Whichever is faster
> UI is client-side; purchases are authoritative server logic.

? What keeps a square icon square on every screen?
- `TextScaled`
+ `UIAspectRatioConstraint`
- `UIPadding`
- `AutomaticSize`
> It fixes the ratio while letting scale-based sizing adapt.
:::

## Challenges

:::challenge easy | Health bar HUD
Build a health bar: a background Frame with a fill Frame inside it, plus a TextLabel showing `75 / 100`. A LocalScript updates the fill's width with `UDim2.fromScale(health / maxHealth, 1)` whenever the local character's health changes, and tweens the width smoothly. Make sure it keeps working after respawning.
@solution
```roblox title="StarterGui › HUD › HealthController (LocalScript)"
local Players = game:GetService("Players")
local TweenService = game:GetService("TweenService")
local player = Players.LocalPlayer

local gui = script.Parent
local back = gui:WaitForChild("HealthBack") :: Frame
local fill = back:WaitForChild("Fill") :: Frame
local label = back:WaitForChild("Label") :: TextLabel

local function bind(character: Model)
	local humanoid = character:WaitForChild("Humanoid") :: Humanoid
	local function render()
		local pct = math.clamp(humanoid.Health / humanoid.MaxHealth, 0, 1)
		TweenService:Create(fill, TweenInfo.new(0.2), { Size = UDim2.fromScale(pct, 1) }):Play()
		fill.BackgroundColor3 = Color3.fromRGB(230, 70, 70):Lerp(Color3.fromRGB(80, 220, 120), pct)
		label.Text = `{math.ceil(humanoid.Health)} / {humanoid.MaxHealth}`
	end
	humanoid.HealthChanged:Connect(render)
	render()
end

player.CharacterAdded:Connect(bind)
if player.Character then bind(player.Character) end
```
With `ResetOnSpawn = false` on the ScreenGui, the LocalScript survives respawns, so binding on `CharacterAdded` is required.
:::

:::challenge medium | Notification toasts
Create a `Notify` RemoteEvent. The server can call `notify:FireClient(player, message)`. On the client, each message appears as a toast at the top of the screen inside a frame with a `UIListLayout`, slides/fades in, stays 3 seconds, then fades out and is destroyed. Multiple toasts should stack.
@solution
```roblox title="StarterGui › Toasts › ToastController (LocalScript)"
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local TweenService = game:GetService("TweenService")
local notify = ReplicatedStorage:WaitForChild("Notify") :: RemoteEvent

local container = script.Parent:WaitForChild("Container") :: Frame -- has a UIListLayout
local template = script:WaitForChild("ToastTemplate") :: TextLabel

notify.OnClientEvent:Connect(function(message: string)
	local toast = template:Clone()
	toast.Text = message
	toast.TextTransparency = 1
	toast.BackgroundTransparency = 1
	toast.Parent = container

	local fadeIn = TweenInfo.new(0.25)
	TweenService:Create(toast, fadeIn, { TextTransparency = 0, BackgroundTransparency = 0.2 }):Play()

	task.delay(3, function()
		local out = TweenService:Create(toast, TweenInfo.new(0.4), { TextTransparency = 1, BackgroundTransparency = 1 })
		out:Play()
		out.Completed:Wait()
		toast:Destroy()
	end)
end)
```
:::

:::recap
- ScreenGuis live in StarterGui → copied to PlayerGui. Usually set `ResetOnSpawn = false`.
- `UDim2` = scale (fraction) + offset (pixels). Center with scale 0.5 + `AnchorPoint` 0.5.
- Layouts, padding, corners, strokes and constraints make UI responsive and polished. Test with the Device Emulator.
- Script UI in LocalScripts: watch data → re-render. Buttons use `Activated`; actions go to the server via remotes.
- BillboardGui and SurfaceGui put UI in the world.
:::
